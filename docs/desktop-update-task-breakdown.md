# The World / worldbase — 在线更新双仓实施任务拆分表

更新时间：2026-05-17  
适用对象：`worldbase` 同事、`the-world` 同事、联调负责人、发布负责人

## 1. 目标

按仓库直接拆出可执行任务，完成以下交付：

- `the-world` 新增“关于与更新”页面。
- `worldbase` 成为桌面端统一更新 API 与下载分发入口。
- Windows x64 完成“检查更新 -> 下载 -> 校验 -> 启动安装”的闭环。
- 双仓不再各自维护真实版本信息。

## 2. 开发范围与顺序

推荐顺序：

1. 先收口发布真相与 Cloudflare 托管路径。
2. 再完成 `worldbase` 的数据读取与 API。
3. 再完成 `the-world` 的主进程更新服务和 About 页。
4. 最后做联调、灰度和发布演练。

## 3. 里程碑

| 里程碑 | 目标 | 完成条件 |

## 5. worldbase 任务单

## 5.1 `WB-01` 设计 Cloudflare 发布存储布局

负责人：`worldbase` 基础设施 / 发布同事  
优先级：P0

任务内容：

- 选定 R2 Bucket、下载域名、官网域名。
- 确定 `desktop/{channel}/{platform}/{arch}/{version}` 的路径布局。
- 确定 `current/` 别名路径策略。
- 确定缓存头策略。

输出物：

- R2 路径约定文档。
- Cloudflare 绑定与域名配置清单。
- 缓存策略清单。

验收标准：

- 团队对下载域名、R2 路径和缓存头无分歧。
- `latest.yml` 与 `release.json` 明确不会被长时间缓存。

## 5.2 `WB-02` 接入 canonical release manifest 读取

负责人：`worldbase` 后端 / API 同事  
优先级：P0

任务内容：

- 增加发布读取层，从 Cloudflare 存储读取 `release.json`。
- 将当前静态 `lib/releases.ts` 从“唯一真相源”降级为开发占位或彻底替换。
- 建立 manifest 校验逻辑：字段完整性、版本、URL、哈希、平台、渠道。

输出物：

- 统一发布读取模块。
- manifest 解析与校验逻辑。

依赖：

- `WB-01`

验收标准：

- 官网所有页面和 API 都能从同一发布读取层获取版本数据。
- 不再需要手工维护真实版本号和真实包 URL。

## 5.3 `WB-03` 实现客户端更新接口

负责人：`worldbase` 后端 / API 同事  
优先级：P0

任务内容：

- 新增 `GET /api/app-update/latest`。
- 按 `channel + platform + arch + current` 返回标准响应。
- 处理 `update_available`、`up_to_date`、`unsupported_platform`。

输出物：

- 客户端更新接口。
- 错误语义与状态码处理。

依赖：

- `WB-02`

验收标准：

- Windows x64 新旧版本都能得到正确响应。
- 官网接口字段与契约一致。

## 5.4 `WB-04` 重构官网版本展示接口

负责人：`worldbase` 后端 / API 同事  
优先级：P1

任务内容：

- 让现有 `GET /api/releases` 从统一发布源返回数据。
- 支持 `channel`、`latest=1` 查询。
- 对官网展示字段做格式化适配，但不得篡改版本真相。

输出物：

- 统一后的 `api/releases`

依赖：

- `WB-02`

验收标准：

- 官网更新页与下载页展示版本与客户端更新接口一致。

## 5.5 `WB-05` 重构官网下载跳转

负责人：`worldbase` 后端 / API 同事  
优先级：P1

任务内容：

- 保留 `GET /api/download/:slug` 对浏览器用户的入口价值。
- 由统一发布源解析 slug，对应当前展示版本的推荐安装包。
- 记录下载计数后再 302 跳转。

输出物：

- 新下载跳转逻辑。
- 下载统计保持兼容。

依赖：

- `WB-02`

验收标准：

- 浏览器点击下载按钮能拿到最新可用包。
- 不存在写死第三方 URL 的残留逻辑。

## 5.6 `WB-06` 调整下载页与更新页

负责人：`worldbase` 前端同事  
优先级：P1

任务内容：

- 下载页使用统一发布读取层提供的数据。
- 更新页使用统一发布读取层提供的数据。
- 明确显示版本、发布时间、更新日志、平台包信息。

输出物：

- 更新后的 `/downloads` 页面。
- 更新后的 `/updates` 页面。

依赖：

- `WB-03`
- `WB-04`

验收标准：

- 页面展示与 `api/releases`、`api/app-update/latest` 保持一致。

## 5.7 `WB-07` 配置缓存与统计

负责人：`worldbase` 基础设施 / API 同事  
优先级：P1

任务内容：

- 为 manifest 和更新接口配置短缓存或 no-cache。
- 为安装包与 blockmap 配置长缓存。
- 校验 D1 下载统计不因重构被破坏。

输出物：

- 缓存配置。
- 统计回归结果。

依赖：

- `WB-05`

验收标准：

- 发布新版本后，客户端 1 分钟内能看到新版本。
- 下载统计仍然可用。

## 6. the-world 任务单

## 6.1 `TW-01` 主进程应用信息接口

负责人：`the-world` 主进程同事  
优先级：P0

任务内容：

- 新增当前应用基础信息读取能力。
- 暴露 `productName`、`version`、`platform`、`arch`、`channel`、官网 URL。
- 通过 preload 向渲染层暴露只读接口。

输出物：

- `app:getAboutInfo` IPC
- preload 暴露接口

依赖：

- `M0`

验收标准：

- 渲染层无需猜测当前版本，可直接显示准确版本信息。

## 6.2 `TW-02` 主进程更新服务

负责人：`the-world` 主进程同事  
优先级：P0

任务内容：

- 新增 UpdateService。
- 调用官网 `GET /api/app-update/latest`。
- 解析 `update_available`、`up_to_date`、`unsupported_platform`。
- 维护更新状态机与错误语义。

输出物：

- 更新服务模块
- `appUpdate:check`
- `appUpdate:getState`
- `appUpdate:onStateChanged`

依赖：

- `WB-03`

验收标准：

- 能稳定查询官网更新接口。
- 状态机在检查成功、失败、无更新、有更新时都正确流转。

## 6.3 `TW-03` About 页渲染层 UI

负责人：`the-world` 渲染层同事  
优先级：P0

任务内容：

- 在设置中心新增“关于与更新”一级分类。
- 显示当前版本、平台、架构、渠道。
- 显示更新状态、更新时间、更新说明。
- 提供“检查更新”“下载更新”“安装更新”“打开官网更新页”按钮。

输出物：

- About 页组件
- 设置中心入口

依赖：

- `TW-01`
- `TW-02`

验收标准：

- 不需要打开开发者工具即可完整完成检查更新操作。
- 状态展示清晰，失败原因可见。

## 6.4 `TW-04` 下载与安装执行

负责人：`the-world` 主进程同事  
优先级：P0

任务内容：

- 主进程下载 Windows 安装包。
- 写入用户数据目录下更新缓存目录。
- 执行 `sha256` / `sha512` 校验。
- 校验通过后允许启动安装程序。
- 校验失败时清理损坏文件并上报错误状态。

输出物：

- `appUpdate:download`
- `appUpdate:install`
- 下载进度事件

依赖：

- `TW-02`

验收标准：

- 能在真实网络环境下载并校验安装包。
- 渲染层不能绕过主进程直接执行文件。

## 6.5 `TW-05` 状态持久化与事件订阅

负责人：`the-world` 主进程 + 渲染层同事  
优先级：P1

任务内容：

- 保存最近检查时间、最近发现版本、最近下载文件路径。
- About 页重新打开后能恢复状态。
- 用事件订阅方式刷新下载进度和错误提示。

输出物：

- 状态持久化逻辑
- 事件订阅接入

依赖：

- `TW-02`
- `TW-04`

验收标准：

- About 页切换后状态不丢失。
- 下载过程进度能实时刷新。

## 9. 风险清单

| 风险 | 仓库 | 说明 | 应对 |
|------|------|------|------|
| 真实版本仍由官网手填 | worldbase | 会再次形成双真相 | 强制以 `release.json` 为唯一真相 |
| `latest.yml` 被 CDN 缓存 | worldbase | 客户端看不到新版本 | 缩短缓存或禁用缓存 |
| 渲染层直接执行安装包 | the-world | 安全与权限边界错误 | 所有下载和执行都走主进程 |
| macOS 自动更新被一并纳入本期 | joint | 复杂度爆炸 | 首期限定 Windows x64 |
| 下载完成但未校验 | the-world | 损坏包可能被执行 | 下载后强制校验哈希 |

## 10. 完成定义（Definition of Done）

以下全部满足，才能宣布本期完成：

- `worldbase` 官网页面与 API 全部来自统一发布源。
- `the-world` About 页可展示版本并检查更新。
- Windows x64 可完成下载、校验、启动安装。
- 双仓不再手工维护两套真实版本信息。
- 联调与发布演练各完成一次并留档。
